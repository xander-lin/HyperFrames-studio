# Hyprframes MyStudio

一个独立的桌面端 Hyperframes Studio，带**画布批注**，把「我想让 AI 改哪儿」
直接变成结构化提示词送进 OpenCode。

> 痛点：用 Hyperframes 做片子，想让 AI 改个东西，得自己截图、自己画标注、
> 自己看当前是第几秒、再解释是哪个元素。
> 这个项目把那些步骤消掉：在画面上画两笔，剩下的自动带齐。

## 它是什么 / 不是什么

**是**：Electron 封装的 Studio（fork 自 `@hyperframes/studio`），加了圈选/箭头/手绘批注，
生成的提示词带**时间点 + composition + 元素标识 + 该帧干净截图**，投递给 OpenCode 插件。

**不是**：不是 AI 客户端。本项目**不做任何 AI 交互**——不发模型请求、不做对话 UI、
不管理上下文。那部分是 OpenCode 的职责，它已经做得很好。我们只负责在正确的时刻
把正确的话送到正确的输入框。

## 工作方式

```
┌───────────────────── MyStudio 桌面端 ─────────────────────┐
│  Electron 主进程                                          │
│  ├─ 起 `hyperframes preview`（Studio 的后端，复用上游）    │
│  ├─ app server（同源托管 Studio + 反代 /api + 桥接端点）   │
│  └─ 存帧 / 投递                                          │
│                                                          │
│  渲染进程：Studio fork + src/annotate 批注层              │
│  ├─ 圈选 / 箭头 / 手绘  →  归一化坐标                     │
│  ├─ 抓该帧 PNG（走 preview 的 thumbnail 接口）             │
│  └─ 渲染提示词 → POST /__mystudio/deliver                 │
└──────────────────────────────────────────────────────────┘
                            │  HTTP（回环）
                            ▼
┌──────────────── OpenCode 插件 ────────────────┐
│  收件箱 :47812                                 │
│  → 只投给已订阅这个 appId 的会话（无人订阅则排队）│
│  → session.prompt({ delivery:"queue", resume:false }) │
└───────────────────────────────────────────────┘
```

`delivery:"queue" + resume:false` 是产品边界的技术实现：**批注排进用户的待处理队列，
不打断、不自动执行**，由用户自己的下一次交互消费。

## 「送进哪一个会话」：订阅制

OpenCode 的多个窗口**共用一个 server 进程**，插件跑在里面，看不到哪个窗口有焦点。
所以它无法"知道"该送给谁——任何自动判断都是猜。

这个项目不做这个猜测：**由会话自己声明**。

```
MyStudio 实例                          OpenCode 会话
  发布 presence ──►  <runtime>/mystudio/apps/<appId>.json
                     {appId, projectDir, projectName, endpoint, heartbeat}
                                              │
                              在对话里让 agent 运行
                              mystudio_apps      → 列出正在运行的应用（含项目路径）
                              mystudio_subscribe → 订阅其中一个
                                              │
                     <runtime>/mystudio/subscriptions/<appId>/<sessionID>.json
                     {appId, sessionID, pluginEndpoint, ...}
                                              │
  发送时的投递 ◄──────────────────────────────┘
  → 读该 appId 的订阅者 → 逐个 POST 到各自 pluginEndpoint
  → 每个请求都带 targetSessionID，插件不再做任何选择
```

几个直接结果：

- **多窗口同时订阅，全部都能收到**：一次投递扇出到所有订阅者，界面显示
  `Sent to 2 conversations`。这正是"多个 agent 同时订阅，每个人都能收到"。
- **多个应用同时开着，订阅时要挑一个**：presence 是**按启动实例**区分的，
  同一项目的两个窗口是两个 appId。`mystudio_subscribe` 在候选不唯一时**拒绝并列出候选**，
  绝不替用户选——选错的后果（提示词进了另一个窗口）是不可见的。
- **`appId` 是唯一的裁决点**，不是目录、不是时间戳：目录只能用来在候选里消歧。
- **没人订阅**：投递进 outbox 并显示 `Queued`，不丢失、也不谎称已送达。
  只要有人订阅，落盘的记录会由该项目的插件实例补投。
- **多个 OpenCode server**：每个插件的收件箱会顺延端口，订阅记录里带的是**写它的那个插件**
  的 endpoint，所以应用能同时投给不同 server 上的会话。

「谁在收」在界面里可见（Sprite → Interface → Conversations）。
没有订阅时它会直接给出下一步：让 agent 运行 `mystudio_subscribe`。

## 快速开始

```bash
pnpm install
pnpm build           # protocol → studio-shell → desktop
```

### 装 OpenCode 插件

在**你的视频项目目录**的 `opencode.json` 里加上插件路径（**必须指向目录**）：

```json
{ "plugin": ["/absolute/path/to/hyprframes-mystudio/packages/opencode-plugin"] }
```

然后启动一个**常驻**的 opencode（TUI 或 serve）：

```bash
cd /path/to/your-video-project
opencode
```

插件起来后会打印：
```
[mystudio] Inbox ready at http://127.0.0.1:47812/annotations
```

> 用 `opencode run "..."` 不行：那是一次性执行，跑完插件就退出（见 `found.md` F-010）。

### 启动桌面端

```bash
cd packages/desktop
npx electron . /path/to/your-video-project
```

不传目录会弹出目录选择框。

**窗口大小**：默认 1680×1020，最小可缩到 **420×340**（约为 1920×1080 屏幕的一半以下），
方便与浏览器、编辑器并排。布局会随窗口收窄：预览保底、两侧栏退让、工具栏改为滚动。
小精灵的 `Interface` 页顶部显示当前项目名称与完整路径，下面是 **Open project…**（换一个项目）。

## 批注怎么用

批注层**不占版面**：它浮在画面上，Studio 的布局一动不动。

1. 按 `A` 进入标注模式（窗口从「可见但不可交互」变成「完全接管输入」）
2. 用工具条或数字键选工具：`1` 圈选 / `2` 箭头 / `3` 手绘 / `4` 浏览
3. 在画面上拖一下，写出这一处想怎么改
4. 按 `S` 把这条批注的块引用（如 `Region 1`）插进提示词框
5. 接着写自己的话；可以再画第二条、再按 `S`
6. 点提示词框末行那个小圆钮发送

**圈选**：只框区域，不绑定元素。适合「这块太暗了」这种整体意见。
**箭头**：从元素拖向目标位置，自动记录尾部所指的元素（`data-hf-id` / 选择器 / 包围盒）。
适合「把这个挪到那儿」。
**手绘**：随手勾画，适合在画面上做记号。

提示词框里**只显示块引用**，坐标与截图路径不摊给用户看；发送时会把它们完整附在
正文下方（`renderUserPrompt`），所以 `Region 1` 在模型那里是有具体含义的。

每条批注都自动带上：composition 路径、精确时间点、画布尺寸、该帧干净截图，
截图还会作为**附件**随消息送出，不只是正文里的一个路径。

### 界面上的三根轴

| 操作 | 作用 |
|---|---|
| `H` | 只切窗口可见性，不影响能否输入、是否激活 |
| `A` | 只切激活：激活时下层 Studio 完全不响应；未激活时窗口仍在、可拖动，但不接受任何输入 |
| 拖动标题栏 | 移动窗口（未激活时也能拖） |
| 右下角缺口手柄 | 调整大小，**只有激活时**才有 |

`E` 只在**视频真的全屏**时接管（那时版面里没有 Design 面板的位置），
它把 Studio 自己的 Design 面板整个搬进浮层；非全屏时 `E` 留给 Studio。

右侧贴着窗口边缘的是**屏幕小精灵**：`Interface` / `Tools` / `Panels` 三个标签，
只列出**此刻真能按**的快捷键，鼠标悬停有解释。顶栏可以整条隐藏，
功能由小精灵接管。

## 快捷键

**默认纯鼠标模式**——Studio 原有的单键快捷键全部禁用（`J/K/L`、`F`、`S`…），
因为视频创作是空间性的，让用户先背快捷键是门槛而不是效率。

只保留两个安全阀，都有明确理由（见 `src/annotate/shortcutPolicy.ts`）：
- `Escape`：取消进行中的笔触，**没有鼠标等价操作**
- `Enter`：提交输入框里正在编辑的内容

批注层自己的键（都在 UI 上有对应鼠标入口，**全部带 `Ctrl`**）：
`Ctrl+A` 激活、`Ctrl+H` 显隐、`Ctrl+S` 把最新一笔追加到提示词、
`Ctrl+Z` / `Ctrl+Shift+Z` 撤销与重做绘制、`Ctrl+E` 属性浮层（仅全屏）、
`Ctrl+Shift+1/2/3/4/5` 切工具、`Ctrl+B` 切白板、`Ctrl` `+`/`-`/`0` 缩放。

**缩放分两个界面，各记各的**：激活标注时，`Ctrl` `+`/`-`/`0` 缩放**批注层**
（工具栏、提示词框、面板）；未激活时缩放 **Studio**。理由很实际：调大工具栏是为了点得准，
不该顺带把底下的编辑器重排一遍；而放大看时间线时，也不该让绘图工具盖满画面。
这与 `A` 决定「谁接收输入」是同一条规则——缩放跟着输入走。画布本身**永不缩放**：
批注坐标是相对视频像素归一化的，缩放它会把已有的标记全部挪位。

### 谁拥有键盘

只有两个状态，规则各一句：

| 状态 | 键盘归谁 |
|---|---|
| 激活（`Ctrl+A` 开） | **全部归批注层**。不认识的键也拦截，Studio 一个都收不到；但不 `preventDefault`，所以文本框里照样能打字 |
| 未激活 | **一个都不归批注层**。除了把它叫回来的那几个键，其余全交给 Studio 与浏览器 |

「一个都不归」是按**命令是否只存在于激活态**判定的：未绘制态下 `Ctrl+Z` 根本不被认领，
连 `keyup`/`keypress` 都不碰。命令会在未激活时返回 false，但「不执行」不等于「不认领」——
认领了就会把整个按键吞掉，下游再也收不到。

### 怎么进出

| 动作 | 进入 | 退出 |
|---|---|---|
| 键盘 | `Ctrl+A` | `Ctrl+A` |
| 鼠标 | 无（工具按钮本身要先激活） | **点击画面之外的空白** |

点击**画面内**不会退出——那是「看一眼我要标注的东西」。退出条件是「点在画面之外」，
不是「没点到控件」。

三条显式例外：`Escape`/`Enter`（安全阀，永远放行）、**文本框的选义键**
（`Ctrl+A`/`C`/`V`/`X`/`Z`，两个状态下都属于文本框）、
`Ctrl` `+`/`-`/`0`（缩放要在两个界面间路由）。规则只在 `keyOwnership.ts` 一处。

### `Ctrl+S` 到底加了什么

它同时做两件事，互不替代：

1. **块引用**：有可引用的图形（圈选 / 箭头）就追加 `Region 1` / `Arrow 2`；
2. **截图**：**状态有变化时**重抓一张该帧的干净图。

「状态有变化」的判断依据是签名：帧 + 该帧上所有存活笔迹（几何 / 颜色 / 粗细）+ 当前选中的元素。

| 你做的事 | 结果 |
|---|---|
| 画一笔，按 `Ctrl+S` | 出一张图（含这一笔）|
| 再按一次 `Ctrl+S` | **不重抓**，还是那张 |
| 再画一笔 | 自动重抓，图里有两笔 |
| 撤销一笔 | 自动重抓，图里少了那一笔 |
| 选中元素 A，再选中元素 B | 换选会更新；重复选 A 不更新 |

提示词框底部会显示 `✎ 00:12.500` 这类徽标：表示**这一帧的图会随请求一起发出**（含你的笔迹）。
撤销掉最后一笔后徽标会消失，不会声称一张不存在的图。徽标数据取自实际投递的
`bundle.ink`，不是内部缓存。

块引用描述的是**内容**：区域用图说明「圈住了什么」，不打印坐标（没有图时才退回去）；
箭头必须给两个点，因为位移就是它的含义；元素块同时给图与元素描述（tag / selector / text / 源码）。

**文本框优先于命令**：`Ctrl+Z` 在提示词框里是**文本撤销**，不是绘画撤销。绘画撤销用工具栏按钮
或把光标移出文本框后按。同理 `Ctrl+A` 在框里是「全选」。

**Studio 的快捷键不动**：早先为了避让，把 Studio 的 undo/redo/标签页/剃刀键搬到了别处，
结果未激活时 `Ctrl+Z` 什么都不做。现在按状态分工，Studio 的键全部保持原位；
只有 `Ctrl+A`（我方在未激活时也要用）让 `select-all-captions` 换成 `Ctrl+Shift+A`。

预览**换页**（切 composition、软重载）后，iframe 内那份监听会随旧窗口消失，所以每次导航后重装;
顶层那份**只装一次**——capture 阶段按注册顺序执行，重装会把自己排到 Studio 后面。

**为什么必须带修饰键**：裸字母是打字键。`s` 在任何文本框里都必须输出 `s`，
数字行必须输出数字；把裸键绑成动作，就意味着每一次误触都会做用户没要求的事。
修饰键把按键变成**命令**，归属也就清楚了。

### 可配置的快捷键

小精灵（右边缘绿色圆点）→ **Keys** 页：

- 点某一行右侧的组合键，按下想用的组合即可（`Escape` 取消，`Backspace` 清空绑定）。
- 每一项都带「恢复默认」，整页还有「Reset all」。
- 冲突会被拒绝并说明是谁占用了——两个动作抢一个键意味着其中一个永远按不出来。

### 一个键只能有一个主人

Studio 自己也有一套快捷键。和它**共享**一个组合键的后果不是"看谁先响应"，
而是**一次按键做两件事**：`Ctrl+1` 曾同时切工具并激活 Compositions 标签页。

为什么 `stopImmediatePropagation()` 救不了：它只能阻止**尚未执行**的监听器，
而同一 target、同一阶段的监听器按注册顺序执行。Studio 的热键监听器注册很早，
我们的会随 iframe 重注册，于是排在它后面——轮到我方时，标签页已经切完了。

所以处理方式是**消除第二个主人**，而不是抢着 stop：

| Studio 的动作 | 原本的键 | 现在 |
|---|---|---|
| Compositions / Assets 标签 | `Ctrl+1` / `Ctrl+2` | `Alt+1` / `Alt+2` |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z` | `Alt+Z` / `Alt+Shift+Z` |
| 全选字幕 | `Ctrl+A` | `Shift+Ctrl+A` |
| 剃刀工具 | `Ctrl+B` | `Alt+B` |

工具键用 `Ctrl+Shift+1..5`：Studio 的快捷键语法**无法表达** `shift+数字`，
所以这是结构性不冲突，不依赖任何表的正确性。

**不是所有键都可配置**，规则按「这个键属于谁」分三层：

| 层级 | 例子 | 可改 | 原因 |
|---|---|---|---|
| 标注层自己的命令 | `Ctrl+A`、`Ctrl+S`、`Ctrl+1` | ✅ | 这些键在本层出现前用户没按过，无习惯可破坏 |
| 安全阀 | `Escape` | ❌ | 没有鼠标等价操作，可解绑就等于把自己锁死 |
| 不属于我们 | `Ctrl+C/V`、`Ctrl+W/Q`、`Ctrl+±` | ❌ | 浏览器／桌面所有，开放改写等于承诺改我们不控制的东西 |
| Studio 已占用 | 标签、播放、时间线的键 | ❌ | 共享会让一次按键做两件事；Keys 页会指出占用者 |

Keys 页底部「Keys that stay fixed」把这些固定键连同原因列出来，
因为「我的快捷键怎么不在列表里」是这个功能一定会收到的第一个问题。

绑定只存**改动过的项**（`localStorage` 的 `mystudio:keymap`），
所以升级后新增的命令仍跟随默认值。

## 选中策略

整个应用**默认不可选中文本**：按钮文案、面板标题、属性行、提示文字都不是拿来复制的，
在它们上面拖动是「挪窗口 / 按按钮」的手势，浏览器回一片蓝色高亮只会像 bug。

放行的只有「有光标、且选字是功能本身」的地方：输入框、`textarea`、`select`、
`contenteditable`（含**代码编辑器**和合成画面里的文本编辑）、以及提示词框。

## 打开项目

小精灵 → **Interface**，顶部显示**当前项目的名称与完整路径**，
下面就是 **Open project…**（换一个项目）。也可以在启动时直接给目录。
选中的目录有两种形状都会被识别：

- **它本身是项目**（有 `index.html` + `hyperframes.json`/`package.json`）→ 直接打开；
- **它装着若干项目** → 列出所有子目录里符合条件的，让你选一个打开。

一个都不是，会明确告诉你「看了 N 个子目录，没找到」，
而不是笼统地说「不是项目」。

## 绘制即生效

拖动即留下笔迹，**结束时不弹任何确认框**——刚落下的这一笔，就是用户要的那一笔。

- `Ctrl+S`：把最新一笔的块引用（`Region 1` / `Arrow 2`）**另起一行追加**到提示词框末尾，
  原先写的内容不动。可以「画一笔 → `Ctrl+S` → 写一句 → 再画 → 再 `Ctrl+S`」。
- `Ctrl+Z` / `Ctrl+Shift+Z`：撤销与重做最近一笔。
  若它**已经**通过 `Ctrl+S` 进入提示词，则不删除标记，而是把对应块标红
  （块序号不能变，否则用户句子里的 `Arrow 3` 会悄悄指向别的标记）。
  这个组合键在提示词框里也优先作用于绘制，而不是文本撤销。
  工具栏上的 `↺` / `↻` 是同一对动作的按钮版——只有快捷键、没有按钮的功能等于藏起来。
- 橡皮擦（`Ctrl+5`）：点击擦掉碰到的笔迹；**长按橡皮擦按钮**清空所有时间点上的所有绘制。
- 已撤销/已擦除的笔迹**从画面上消失**；它在提示词里的块留在原位并变红划线——
  序号不跳，所以你写的那句话仍然指着它，只是被明确标成「已作废」。

策略可换：`PERMISSIVE_POLICY` 恢复上游手感。

## 白板

有时要解释的东西**不在画面上**——想画的是意图本身、一个布局、或手写一句话。
在素材上叠着画只会让画面和笔迹互相干扰，而且那些笔迹会被当成对这一帧的批注发出去。

所以白板是**临时把视频换成一张同尺寸的白纸**：

- 与视频**尺寸完全一致**，切换时任何东西都不位移；同一位置画的笔画换回来还在同一位置。
- **两边内容互不丢失**。切到白板，视频上的标记还在；切回视频，白板上的笔迹还在。
- **清空互不干涉**：橡皮擦、撤销、清空都只作用于当前显示的那一面。
  这不是靠"记得过滤"实现的，而是**两个独立的 store**——白板笔迹根本不进标注存储，
  标注代码路径看不到它，也就不可能删掉它。
- 白板笔迹**不会被投递**：它是工作草稿，不是请求。
- **四个工具在白板上都能用**（圈选、箭头、手绘、橡皮），但**不编号**。
  白板没有提示词，也就没有 `Region 1` 这样的引用对象；给纸上的方框编号，
  等于给一个永远不会被引用的东西分配标识。

### 翻页

白板是**自己的**一叠纸，页数与视频无关：

- 一开始就是第 1 页；「**+ Page**」在当前页后面插一页，**没有上限**。
  页数不是从时间线的场景数推出来的——那会让白板最多只有视频的剪辑数那么多页。
- **翻页不动视频**。在纸上翻一页只是换一张纸，跟播放头在哪没有关系。
- ◀ / 页号 / ▶ 到两端就停，**不循环**（首页时 ◀ 变灰，末页时 ▶ 变灰）。

翻页和笔都是工具栏上的**二级面板**：

- 翻页面板在白板模式下**常驻展开**，不是点一下才出现——翻页、加页属于「换一张纸」这个
  动作本身，让用户先点开菜单是凭空多一步。
- 面板**从工具栏侧面长出来**，方向按工具栏**当前位置**决定：工具栏在窗口左半边就朝右开，
  在右半边就朝左开。拖动工具栏时会**边拖边换边**，不用等松手。
- 面板是工具栏的**子元素**，不是独立浮层：所以它跟着工具栏走、不新增图层，
  也不受工具栏滚动区的裁剪。整体用**淡绿色**（主题 accent 调淡），表示它是那个控件的附庸。
- 面板本身很紧凑：翻页面板只有一行 `◀ 3 / 18 ▶ +`。

> 为什么不是一条进度条、也不是一列页码按钮：
> 进度条回答「我走到哪了」，不是「怎么翻过去」；
> 一列页码按钮的长度会随页数增长，把旁边的工具全挤走，
> 而真正有用的「第 4 / 30 页」反而最难看见。

### 笔

**颜色和粗细是两个独立按钮**，各自开自己的紧凑面板：

- 颜色按钮是一排圆点，点一下即选，选完关闭。
- 粗细按钮 `− 7px +`：七档，换挡式。
  为什么不是七行按钮：那会把面板高度翻倍，而粗细是选一次就不动的东西；
  为什么不是滑块：滑块要求瞄准一个看不见的数值，而换挡只问「更粗还是更细」。
- 两个按钮**在视频模式下也有**。笔就是笔，粗细在素材上和在纸上一样重要；
  白板与视频各存一支自己的笔，按钮上显示的就是当前正在用的那支。
- 触发按钮本身就是当前笔的预览：颜色即填充，粗细即圆点大小。

手写按数位笔的真实输入渲染（压力调粗细、曲线平滑、梯形填充做渐变笔宽），详见下一节。

## 手写笔迹

自由笔是**书写**，不是标注，所以它和区域／箭头走完全不同的路径。

### 它没有编号

区域和箭头是**指代**——「这块」「把这个移过去」。编号让用户能在句子里写
`Arrow 2` 而被人听懂。

手写不是指代，它的意义就是笔画本身。给它编号有两重害处：

1. 编号是位置性的。如果手写也占号，你在两个箭头之间随手划一笔，
   `Arrow 1` 就会变成 `Arrow 2`——而你**已经写好**的那句话会悄悄指向别的标记。
2. 「Freehand 3，84 个点，起点在这、终点在那」对读者毫无用处，
   而这句话恰好把唯一有用的信息（形状）丢掉了。

所以手写不占号、不能进提示词的块列表，也不在画布上带数字徽标。

### 它作为图片发送

手写通过**「用户画过的这一帧」**到达读者：干净帧 + 笔迹，合成成一张图。
图片就是它要传达的全部内容，这正是共享白板上「我把要改的地方圈出来了」的做法。

- 每帧一张图；同一帧上再写一笔会**覆盖**上一张，不是叠加出多张近似图片。
- 尺寸是合成画面自己的尺寸（1920×1080 的片子就出 1920×1080），
  与你的窗口多大、缩放多少无关。
- 笔迹颜色和光晕与应用里一致：白底幻灯片上也要看得见。
- 这一帧的笔迹若被全部撤销，那张图就不会被投递——否则读者会看到你已经删掉的痕迹。

提示词里对应的一节只说清「这是用户画过的那一帧」并给出路径，不再逐笔罗列。

### 笔感：压力与平滑

参照 Rnote 这类写作应用，笔迹按**数字化笔**的真实输入渲染：

- **压力决定粗细**。`PointerEvent.pressure` 从 0 到 1，映射到 1.2–4.6px。
  鼠标报告的是恒定 0.5，而 0.5 是一个合法的「轻按」值——所以不能只看数值，
  必须看 `pointerType`。鼠标／触控板**不记录压力**，用固定宽度；
  否则每一条鼠标线都会是「中等力度」，看上去像压力坏了。
- **平滑**。相邻采样点之间用二次曲线（以采样点作控制点、取中点作端点）重采样，
  所以笔画里没有折角。鼠标快速划过时用 `getCoalescedEvents()` 收回被
  浏览器丢掉的中间采样，否则快速书写会画成多边形。
- **可变宽度用填充轮廓实现**。`ctx.stroke` 的线宽是一个数值，画不出渐变的笔。
  因此每段画成梯形并并集填充，同时避免叠加处变深成「串珠」。

> 当前架构里按下与抬起共用一次指针流，所以没有真正的橡皮擦压感，
> 也没有倾斜（tilt）输入。要支持倾斜需要额外的 `pointerrawupdate` 通道。

## 投递通道与失败处理

`FallbackSink` 先试 HTTP 收件箱，连不上就落盘到 `<项目>/.mystudio/outbox/`：

- 插件在跑 → 立刻进 OpenCode（`HTTP 200`）
- 插件没跑 → **不丢**，暂存磁盘，插件下次起来可消费（`readOutbox`）
- 截图抓不到 → 面板显示黄色警告，不静默吞掉

## 已知限制

- 预览服务由 `hyperframes` CLI 提供，需要机器上能跑 `npx hyperframes`。
- 窗口后端由环境自动选择（`desktop/src/platform.ts`）：有 `WAYLAND_DISPLAY` 用原生 Wayland，
  只有 `DISPLAY` 用 X11，命令行显式指定的 `--ozone-platform` 永远优先。
  **原生 Wayland 是首选**：它让输入法走 `zwp_text_input_v3`，候选窗由 fcitx 自己绘制；
  强制 X11 会把应用变成 XWayland 客户端，只能退回 XIM，输入法皮肤就不生效了。
  （早先这里写的是「Wayland + Vulkan 起不来，用 `--ozone-platform=x11`」，实测为假：
  原生 Wayland 启动正常且完整 GPU 加速，Vulkan 在**两种**模式下都是关闭的。）
- 窗口最小 420×340；再小的尺寸布局虽然不溢出，但预览已经只剩缩略图大小，失去意义。
- 批注目前不持久化成项目内文件（只存在内存 + 截图落盘）；重新打开项目会清空。
- 快捷键配置存在 `localStorage`，按**主机**而非按项目保存。
- 插件与桌面端用固定端口 `47812` 约定；多项目并行时需要改 `MYSTUDIO_INBOX_PORT`。
- 订阅是**按运行实例**的：MyStudio 重启后 appId 变了，需要在对话里重新订阅一次。
  这是刻意的——`appId` 代表"这个窗口"，重启后它就不是同一个窗口了。
- `session.viewed` 仍然被跟踪，但只作为**没有钉子的历史 payload**（旧 outbox 记录、手工 POST）
  的回退；正常投递走订阅，不经过它。
